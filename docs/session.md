# Session Lifecycle & Consistency Semantics

> Single source of truth: [src/session.ts](../src/session.ts), [src/types.ts](../src/types.ts), [src/system-prompt.ts](../src/system-prompt.ts), [src/compaction.ts](../src/compaction.ts).

## Persistence Granularity & Consistency

- **Message-level incremental persistence**: Before executing `prompt()` or `continue()`, the harness persists the user input with `status: "running"`; if pre-run persistence fails, execution does not start. As each message finishes (`message_end`, aligned with `pi-coding-agent`), the snapshot is saved incrementally with `status: "running"`, and when the run settles, the terminal status is committed. Streaming token deltas (`message_update`) remain live previews — UI hosts should consume incremental events (`message_start` / `message_update` / `message_end` / `tool_execution_*`) while streaming and sync committed history from `getSnapshot()` on open or `result.snapshot` once `prompt()` / `continue()` resolves (not inside `message_update` or `agent_end`).
- **Terminal status & cancellation**: `pi-agent-core` encodes model errors and cancellation in the final `AssistantMessage.stopReason` (`"error" | "aborted"`) rather than rejecting `prompt()`. The harness derives `idle` / `aborted` / `error` from abort intent and `stopReason`, drops empty `aborted` trailing messages, and keeps non-empty partial `aborted`/`error` messages for host display (skipped on subsequent turns by `pi-ai`).
- **Save-failure rollback**: If any mid-run `message_end` or final `save()` fails, the run aborts immediately, in-memory state rolls back to the last successfully persisted snapshot, and the handle is marked `SESSION_INVALIDATED` so memory and storage never diverge.
- **Crash recovery**: Opening a session whose persisted status is `"running"` immediately transitions it to `"interrupted"`, preserving every message persisted before the crash without replaying unfinished model or tool calls and without synthesizing fake tool results on disk (matching `pi-coding-agent`, where `@earendil-works/pi-ai`'s `transformMessages()` transparently handles any trailing orphaned `toolCall` on the next `prompt()`). Hosts may then call `prompt()` or explicitly `continue()`.
- **Deferred model resolution on open**: `openSession()` succeeds without mutating storage even if the stored `ModelRef` is no longer present in `Models` (`session.resolvedModel === undefined`), keeping history inspection, `getStats()`, `setTitle()`, `setModel()`, and `fork()` working while rejecting `prompt()` / `continue()` / `compact()` with `MODEL_NOT_FOUND` until a valid model is explicitly selected via `setModel()` (or restored in `Models`).

## System Prompt Ownership

`pi-agent-core` persists system prompts and tool declarations as `role: "system"` messages in the transcript and ignores `initialState.systemPrompt` when reopening a transcript that already starts with a system message. On reopen, the harness preserves the transcript and appends a `system` patch message only when the host's `systemPrompt` differs from the active baseline, preserving prompt-cache prefixes ([src/system-prompt.ts](../src/system-prompt.ts)).

## Run Controls & Session Operations

- **Concurrency & live queues**: Concurrent `prompt()` / `continue()` calls reject with `SESSION_BUSY`. During an active run, `steer()` (injected after the current tool round) and `followUp()` (executed after the run would finish) queue messages; calling them while idle throws `SESSION_IDLE`, and `abort()` / run exit clears any unconsumed queue items.
- **Guardrails & non-destructive compaction**: Forwards `sessionId` (provider prompt-cache affinity) and `identity` (defaults to `{ attribution: null }`). Supports optional `maxTurns` tool-turn limits, exponential-backoff `retry` on transient provider errors, and non-destructive checkpoint `compact()` (manual / threshold / overflow) routed through the `session_before_compact` / `session_compact` / `session_compact_failed` extension hook pipeline (with `createDefaultCompactionExtension()` registered as the built-in fallback). Checkpoints append to `snapshot.compactions` without deleting prior messages, while `projectContextMessages()` / `session.getContextMessages()` project `[systemBaseline, summary, ...messages.slice(firstKeptIndex)]` for the model, keeping full history inspectable and forkable without ever splitting `toolCall`/`toolResult` pairs.
- **Management & usage accounting**: `fork()` (new `sessionId` + `parentSessionId`, rejects unsafe tool boundaries), idle-time `setModel()` / `setThinkingLevel()` / `setTitle()`, `reset(handoff?)`, `getStats()` (aggregates turn, tool, and compaction checkpoint usage), and optional `onUsage` callback observing real-time `turn`, `tool`, and `compaction` usage (including failed compaction calls that incurred tokens).
